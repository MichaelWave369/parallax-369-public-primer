# Public Feedback Guide

The Parallax 3–6–9 Public Primer improves through review, not assumption. This file opens a structured channel for public feedback while preserving the repository's publication boundary.

## What feedback is useful

We welcome observations about:

- unclear language or undefined terms;
- difficulty moving through Stage 3, Stage 6, or Stage 9;
- template fields that are confusing, missing, or redundant;
- accessibility barriers in the website or Markdown documents;
- broken links or rendering problems;
- downstream adaptations that reveal compatibility questions;
- examples that accidentally blur specification, implementation, and evidence.

## What not to submit

Do not include:

- private Parallax prompts, skills, orchestration, canon, or project records;
- credentials, secrets, private URLs, client data, or personal conversations;
- confidential product designs or regulated information;
- claims that repository use constitutes certification or professional approval.

If sensitive material is accidentally submitted, remove it immediately and follow the repository's `SECURITY.md` process.

## Feedback receipt

A useful feedback report answers:

1. **Artifact:** Which page, file, template, or stage were you using?
2. **Task:** What were you trying to accomplish?
3. **Observation:** What happened?
4. **Expected outcome:** What would have made the artifact clearer or more useful?
5. **Impact:** Did the issue block use, create ambiguity, or merely slow you down?
6. **Environment:** Browser, assistive technology, device, or Markdown renderer when relevant.
7. **Suggested change:** Optional. A report does not need to contain a solution.

## Status language

Feedback may be classified as:

- `received` — recorded but not yet evaluated;
- `accepted` — approved for a candidate change;
- `declined` — not adopted, with rationale preserved;
- `deferred` — useful but outside the current version scope;
- `needs-evidence` — requires reproduction or additional observations;
- `boundary-blocked` — would expose protected internal material or exceed the public primer's scope.

## Human authority

Feedback can inform a release. It cannot authorize publication, certification, or a change to the public boundary by itself. A human maintainer retains the release decision.

Use the repository's **Public Primer Feedback** issue form to submit a report.
