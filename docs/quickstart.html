Public Candidate v0.4

Start locally.
Keep authority human.

The v0.4 adoption kit creates a six-file project scaffold from public templates, performs no network submission, and preserves specification, implementation, evidence, and field-trial observations as different artifacts.

Read the full quickstart Read the trial protocol
1 · ScaffoldCreate a new local destination with a project manifest and separate Stage 3, 6, 9, and field-trial files.
2 · SpecifyRecord facts, assumptions, unknowns, requirements, risks, authority, and testable acceptance criteria.
3 · BuildConstruct the smallest honest candidate while labeling mocks, simulations, deferrals, deviations, and failures.
4 · ProveRun the acceptance tests, preserve negative evidence, scope claims, and leave release decisions to the human authority.

Create the project

One local command.

python scripts/init_public_project.py \
  --name "Neighborhood Notice Board" \
  --human-authority "Project owner" \
  --output work/notice-board

The command refuses to overwrite an existing destination and uploads nothing.

The scaffold includes

  • a machine-readable project manifest;
  • Stage 3, Stage 6, and Stage 9 documents;
  • a voluntary field-trial receipt;
  • human-authority and privacy boundaries.

The scaffold excludes

  • private prompts or SkillSet logic;
  • telemetry or network submission;
  • autonomous release authority;
  • certification or domain approval.

After the first use

Turn experience into a receipt.

A voluntary, non-sensitive field trial can show where real users become clear, confused, blocked, or overconfident about what validation proves.
