Public Candidate v0.2

Parallax 3–6–9

A human-led method for moving from idea, to implementation, to evidence.

369

The core rule

A specification is not an implementation. An implementation is not evidence. Evidence does not authorize claims beyond its scope.

3

Specify

What are we actually proposing, and what must be true?

  • Preserve original intent and provenance.
  • Separate facts, assumptions, hypotheses, proposals, and unknowns.
  • Define scope, authority, requirements, risks, and non-scope.
  • Write testable acceptance criteria.

Output: Controlling specification and Stage 6 handoff.

6

Build

What is the smallest honest candidate we can build?

  • Keep the controlling specification unchanged.
  • Map each requirement to a component and status.
  • Disclose mocks, simulations, deviations, failures, and deferred work.
  • Record dependencies, commands, and artifact identity.

Output: Candidate, traceability map, and implementation receipt.

9

Prove

What demonstrably works, where, and under which conditions?

  • Run declared acceptance tests.
  • Preserve observations, conditions, failures, and blocked tests.
  • Separate supported from unsupported claims.
  • Return a scoped recommendation to the human authority.

Output: Evidence report and human release decision.

The receipt chain

Intent → Requirement → Implementation status → Test → Observation → Claim boundary → Human decision

Human authority remains

Tools may organize, draft, build, test, and recommend. They may not silently change the target, accept material risk, certify a result, or authorize publication.

Public boundary

This primer teaches a public method. It does not expose private prompts, skill logic, orchestration, canon, project records, credentials, conversations, or accumulated internal intelligence.

No trust laundering: polish is not proof; simulation is not field evidence; repository inclusion is not certification.
