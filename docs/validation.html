Public Candidate v0.5

Checks that can block.
Never checks that can rule.

The public helpers inspect receipts, local project scaffolds, field trials, review bundles, templates, links, static pages, and generated reports. They use Python’s standard library and retain human authority.

Receipt and project shapeValidate required identity, authority, stage separation, evidence, limitations, privacy declarations, and artifact paths.
Field trialsCheck consent declarations, observation structure, project keys, conditions, evidence limits, and pending maintainer decisions.
Review bundlesReject missing files, duplicate sources, trial-ID mismatches, invalid receipts, and cross-project synthesis.
Template and site integrityCheck six public template contracts plus local Markdown, HTML, fragments, entry points, and assets.
Report preservationGenerate proving reports while preserving supplied failures and pending human authority.
Synthesis preservationGenerate review packets that retain both trials, conditions, observations, limitations, divergence, no-score language, and a pending decision.

Authority boundary

A green check is not approval.

The workflow has read-only repository permissions. It contains no merge, deployment, Pages, release, tagging, certification, roadmap, or repository-write step.

Read the validation guide

Helpers may

  • return pass or failure;
  • name missing fields, files, or references;
  • reject cross-project review bundles;
  • block a protected branch when configured by a human;
  • generate local draft reports and packets.

Helpers may not

  • authenticate evidence or consent;
  • score, rank, average, or vote truth;
  • approve risk or authorize release;
  • merge, publish, deploy, tag, certify, or change the roadmap;
  • access private Parallax systems.

Run locally

One command, explicit scope.

python scripts/run_public_checks.py
